## 2026-03-31 - URL Scheme Validation and SSRF Protection in Preflight Checks
**Vulnerability:** `preflight-check.py` disabled TLS certificate verification globally (`ssl.CERT_NONE` and `check_hostname = False`) and allowed arbitrary URL schemes (such as `file:///etc/passwd`) or internal addresses (e.g., `http://127.0.0.1:8765`, `169.254.169.254`), leading to Local File Disclosure (LFD), Man-in-the-Middle (MITM) risks, and Server-Side Request Forgery (SSRF) when URLs are submitted from the dashboard or CLI.
**Learning:** Python's `urllib.request.urlopen` natively supports schemes like `file://` by default unless explicitly restricted. Without scheme enforcement and host IP validation, any component accepting URLs and passing them to `urllib.request` can leak local files or probe internal services.
**Prevention:** Consolidate URL validation into `is_safe_url` in `workspace/scripts/queue_utils.py` to enforce `http`/`https` protocols and verify that resolved IPs do not belong to loopback, link-local, private, or reserved ranges prior to executing network requests. Retain default TLS certificate validation (`ssl.create_default_context()`).
